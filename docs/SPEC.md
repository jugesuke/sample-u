# 船コントローラー 仕様書

水中モーター2基で走る船を、AndroidスマホのブラウザからBluetooth Low Energy(BLE)で操縦するシステムの仕様。

## 1. システム構成

```
Android Chrome(Webアプリ) --BLE--> XIAO ESP32C3(ファームウェア) --PWM--> AM1025EA x2 --> モーター x2
```

| 要素 | 内容 | 場所 |
|---|---|---|
| ファームウェア | Arduino(esp32 core 3.3.12、BLEスタックはNimBLE)、ボード `XIAO_ESP32C3` | `firmware/boat_controller/` |
| Webアプリ | React + TypeScript のPWA。GitHub Pagesで配信 | `webapp/` |

Web Bluetoothはhttpsが必須のため、Webアプリは船から配信せず、GitHub Pagesに置く。

## 2. ハードウェア

### ピン割当

| 信号 | XIAOピン | GPIO | 接続先 |
|---|---|---|---|
| ML_IN_A | D10 | 10 | 左モーター U3 IN_A |
| ML_IN_B | D9 | 9 | 左モーター U3 IN_B |
| MR_IN_A | D8 | 8 | 右モーター U4 IN_A |
| MR_IN_B | D7 | 20 | 右モーター U4 IN_B |

### 電源

単3電池2本。VM、VBATともに電池直結(約2〜3.2V)で、AM1025EAの電源範囲 2.0〜6.8V に収まる。XIAOにはU2(XCL103)で昇圧した3.3Vを供給する。

### AM1025EAの入力

| IN_A | IN_B | OUT_A | OUT_B | 動作 |
|---|---|---|---|---|
| L | L | Hi-Z | Hi-Z | 停止(待機モード) |
| H | L | H | L | 順方向 |
| L | H | L | H | 逆方向 |
| H | H | L | L | ブレーキ |

データシートはp.4とp.5/7で「正轉」の呼び方が逆だが、OUTがINに追従する点は一致している。本仕様では上の表の呼び方を使う。

## 3. モーター制御

| 項目 | 値 |
|---|---|
| PWM | 20kHz、10bit(データシートの入力範囲 20Hz〜65kHz の範囲内) |
| 指令範囲 | -100〜100(%) |
| 指令の変化速度 | 0→100% を約300ms |

**駆動方式:** スローディケイ(片側H固定、もう片側をPWM)。PWMのオフ期間はブレーキ状態になる。L/Lとの交互にしないのは、PWM周期ごとにICが待機モードへ入るのを避けるため(データシートに待機からの復帰時間の記載がない)。

| 指令 | IN_A | IN_B |
|---|---|---|
| 正(出力 d) | 100% | (1−d) |
| 負(出力 d) | (1−d) | 100% |
| 0 | L | L |

**回転方向:** 前進指令で逆に回るモーターは、スケッチ冒頭の `MOTOR_L_INVERT` / `MOTOR_R_INVERT` を `true` にする。

## 4. BLEプロトコル

| 項目 | 値 |
|---|---|
| デバイス名 | `SampleU-Boat` |
| サービスUUID | `7c1f0a10-5b3e-4d2a-9f61-2a8e4c7d1b00` |
| 指令キャラクタリスティックUUID | `7c1f0a11-5b3e-4d2a-9f61-2a8e4c7d1b00` |
| 指令のプロパティ | Write Without Response |
| ログキャラクタリスティックUUID | `7c1f0a12-5b3e-4d2a-9f61-2a8e4c7d1b00` |
| ログのプロパティ | Notify |
| 同時接続数 | 1台。切断後にアドバタイズを再開する |

### 指令フレーム(4バイト)

| バイト | 型 | 内容 |
|---|---|---|
| 0〜1 | uint16(リトルエンディアン) | 通し番号。送信ごとに1増え、65535の次は0に戻る |
| 2 | int8 | 左モーター指令(-100〜100、正が前進) |
| 3 | int8 | 右モーター指令(-100〜100、正が前進) |

- 範囲外の値は ±100 に丸める。
- 4バイト以外のフレームは破棄する(タイムアウトの計測も更新しない)。
- 認証やペアリングはない。Bluetoothの届く範囲にいる第三者も、船が未接続なら接続できる。

### ログ通知

船の動作ログを、改行で終わるテキストとして通知する。1回の通知は最大20バイトで、MTUに依存しない。受信側は改行まで連結して1行にする。

未送信の行は最大64行まで保持し、溢れると古い行から捨てる。購読されると保持していた行から順に送る。保持はRAM上なので、リセットや電源断で失われる。

各行は `<LEVEL> <起動後のミリ秒> <本文>` の形式で、1行の長さは最大119文字。

### 送信周期

Webアプリは接続中、50msごとに最新の指令を送る。値が変わらなくても送り、ハートビートを兼ねる。前の書き込みが完了していなければその周期は飛ばす。

## 5. フェイルセーフ

次のいずれかで、変化速度の制限を通さず、ただちに両モーターを停止(L/L)する。

| 条件 | 検出側 |
|---|---|
| 最後の有効フレームから500ms経過 | ファームウェア |
| BLE切断 | ファームウェア |
| 接続後、最初の有効フレームを受信する前 | ファームウェア |

Webアプリ側では、次の場合に操作入力を中立へ戻す。

| 条件 | 動作 |
|---|---|
| 画面が非表示になった | 停止フレームを1回送り、以後は送信を止める。表示に戻ると再開する |
| 接続が切れた | 送信を止め、STOPのラッチも解除する |
| 指を離した | 入力を0に戻す |

**限界:** 電源投入からファームウェアが動き出すまでの間は、ファームウェアで制御できない(10章の1)。

## 6. Webアプリ

### 対応環境

AndroidのChromeのみ。Web Bluetooth非対応のブラウザ(iPhoneのSafariなど)やhttps以外では案内を表示する。

### 操作モード

上部のタブで切り替える。選択は端末に保存する。

| モード | 操作 | 出力 |
|---|---|---|
| スティック | ジョイスティック1本(片手) | ミキシング |
| 左右独立 | 縦スライダー2本(両手) | 左右をそのまま出力 |
| スロットル+舵 | 縦スライダーで前後進、横スライダーで旋回(両手、横持ち向け) | ミキシング |

**ミキシング:** `左 = 前後進 + 旋回`、`右 = 前後進 − 旋回`。どちらかが ±100 を超えるときは、左右の比率を保って縮める。

スティックには半径の8%の不感帯がある。

### 画面の配置

縦画面では、上に接続とモード、中央に操作部、下に最大出力とSTOPを置く。

横画面では、接続、モード、L/R出力、最大出力、STOPを1列にまとめ、残りの領域全体を操作部に使う。

| モード | 横画面の配置 |
|---|---|
| スティック | 片側に操作部、反対側に共通の列。左右は切り替えられ、選択は端末に保存する |
| 左右独立 | 左右に縦スライダー、中央に共通の列 |
| スロットル+舵 | 左に縦スライダー、中央に共通の列、右に横スライダー |

### 共通の表示と操作

| 要素 | 内容 |
|---|---|
| 接続表示 | 未接続 / 接続中… / 接続済み / 切断済み。切断後は「再接続」と「選び直す」を出す |
| L/R出力 | 実際に送っている指令値を表示する |
| 最大出力 | 10〜100%(5%刻み)、初期値100%。全指令に掛ける。端末に保存する |
| 左右バランス | -100〜100(1%刻み)、初期値0。動かした向きの反対側のモーターを弱める(右へ動かすと右が弱まり、100で右が止まる)。スライダーのほか、◀ ▶ で1%ずつ調整できる。最大出力より先に掛け、端末に保存する |
| STOP | 押すと解除するまで0を送り続ける。接続が切れると解除される |

### ログ画面

「ログ」ボタンで開く。船とアプリのログを、受信または記録した順に表示する。

| 操作 | 内容 |
|---|---|
| 表示レベル | 選んだレベル以上を表示する。初期値はINFO。保存には影響しない |
| 保存 | 全レベルの全行をテキストファイル `boat-log-<日時>Z.txt` としてダウンロードする |
| クリア | ログを消す |
| 閉じる | 操縦画面に戻る |

アプリは最新10000行をlocalStorageに保存する(約1秒ごと、画面を離れるときは即時)。画面には条件に合う最新1000行を表示する。ログ画面を開くと操作入力は中立に戻るが、接続とハートビートは維持する。

### その他

接続中は画面の消灯を防ぐ(Wake Lock API)。PWAとして動作し、一度開けばオフラインでも起動できる。

端末の既定フォントでは漢字が中国語の字形になることがあるため、Google FontsのNoto Sans JPを使う。

## 7. ログ

### 形式

ファイルと画面の各行は次の形式。日時はISO 8601のUTCで、スマホで受信または記録した時刻。

```
2026-11-03T01:15:09.215Z INFO  boat 312 boot reason=POWERON build=Nov  3 2026 16:40:12
```

列は左から、日時、レベル、送信元(`boat` / `app`)、本文。`boat` の本文の先頭は船の起動後ミリ秒。未接続の間に溜まった行は接続後に届くので、船での順序は起動後ミリ秒で判断する。

### レベル

| レベル | 内容 |
|---|---|
| ERROR | 異常なリセット(`POWERON`、`SOFTWARE`、`EXTERNAL` 以外)、接続失敗 |
| WARN | フェイルセーフ停止、通し番号の欠け、不正フレーム、送信の詰まりや失敗 |
| INFO | 起動、接続、切断、画面の表示切替 |
| DEBUG | 問題のない `tx` 行と `rx` 行 |

### 指令の追跡

アプリの `tx` 行と船の `rx` 行で、指令の経路を追跡する。どちらも、値が変わったとき(最短200ms間隔)と、変化がなくても1秒ごとに1行出す。集計値は前回の行からのもの。問題を含む行はWARNになる。

```
tx seq=1234 L=72 R=24 mode=joystick a=30 b=60 max=80 bal=0 stop=0 n=4 skip=0 fail=0
rx seq=1234 L=72 R=24 out=70,30 duty=1023/307,1023/716 n=4 lost=0 gap=58ms bad=0 drop=0
```

| 項目 | 内容 |
|---|---|
| `seq` | 最後に送信した / 受信した通し番号 |
| `L`、`R` | 送信した / 受信した指令 |
| `mode`、`a`、`b`、`max`、`bal`、`stop` | 操作モード、入力値、最大出力、左右バランス、STOP状態(`tx` のみ) |
| `n` | 送信できた / 受信したフレーム数 |
| `skip`、`fail` | 前の書き込みが未完了で飛ばした回数、書き込みの失敗回数(`tx` のみ) |
| `out` | ランプ処理後の左右の出力(`rx` のみ) |
| `duty` | 実際に書き込んだPWM値 `左IN_A/左IN_B,右IN_A/右IN_B`、最大1023(`rx` のみ) |
| `lost` | 通し番号の欠け(`rx` のみ) |
| `gap` | 最大受信間隔(`rx` のみ) |
| `bad` | 不正フレーム数(`rx` のみ) |
| `drop` | 溢れて捨てたログ行数の累計(`rx` のみ) |

### 切り分け

| ログの状態 | 判断 |
|---|---|
| `a`、`b` が操作に反応しない | 操作部の問題 |
| `a`、`b` は動くが `L`、`R` が変わらない | `max`、`bal`、`stop` を確認 |
| `tx` が出ない、`seq` が増えない、`skip`、`fail` が多い | 送信の問題 |
| `tx` の `seq` は増えるが、`rx` の `seq` が追いつかない、`n=0`、`lost` が多い | 無線区間の問題(`tx` の成功はブラウザが受け付けたことしか示さない) |
| `bad` が増える | アプリとファームウェアのフレーム形式の不一致 |
| `rx` の `L`、`R` は正しいが `out` が追従しない | 船の制御の問題、`failsafe stop` の有無を確認 |
| `duty` は出ているがモーターが回らない | 配線、ドライバIC、モーター、電池など回路側の問題 |

モーターの実際の回転や電流を検出する回路はないので、ログで確認できるのは `duty` までである。`rx` 行が届かないときは、ログの通知だけが止まっている可能性もある。

切断理由は、使用しているBLEライブラリのコールバックで取得できないため記録しない。

## 9. 変更時に揃える箇所

次の値はファームウェアとWebアプリの両方にあるので、同時に変更する。

| 値 | ファームウェア | Webアプリ |
|---|---|---|
| UUID | `SERVICE_UUID`、`COMMAND_CHAR_UUID`、`LOG_CHAR_UUID` | `webapp/src/lib/protocol.ts` |
| 指令範囲 | `COMMAND_MAX` | `COMMAND_MAX` |
| 指令フレームの形式 | `COMMAND_FRAME_LENGTH`、`onWrite` | `encodeFrame` |
| ログ行の間隔 | `REPORT_INTERVAL_MS`、`REPORT_MIN_INTERVAL_MS` | 同名の定数 |

送信周期(`SEND_INTERVAL_MS`)は、タイムアウト(`COMMAND_TIMEOUT_MS`)より十分短くする。

## 10. 回路上の注意

回路は製作済みのため変更しない。

1. **起動時にモーターが回る可能性:** D9(GPIO9)はXIAO基板上でプルアップされ、IN_AはICの内蔵100kΩでプルダウンされる。このためファームウェアが動き出すまで、左モーターが L/H で駆動される可能性がある。D8も起動時の状態によっては右モーターに影響する。実機で確認する。
2. **IN入力電圧:** データシートp.2の注記では、IN入力はVCC以下が条件。XIAOのH出力3.3Vは電池電圧を上回り、消耗時ほど差が大きくなる。影響の程度はデータシートから判断できないので、実機で確認する。
3. **コンデンサ:** データシートはモーター端子間の0.1µF(p.6のC4)も必須としている。回路図のC8/C11はICの出力側(p.6のC3)に相当するので、モーター側にも付ける。
4. **USBと電池:** XIAOの3V3にU2の出力が直結されているため、USBと電池は同時につながない。書き込みはXIAOを基板から外して行う。
