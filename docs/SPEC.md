# 船コントローラー 仕様書

水中モーター2基で走る船を、AndroidスマホのブラウザからBluetooth Low Energy(BLE)で操縦するシステムの仕様。

## 1. システム構成

```
Android Chrome(Webアプリ) --BLE--> XIAO ESP32C3(ファームウェア) --PWM--> AM1025EA x2 --> モーター x2
```

| 要素 | 内容 | 場所 |
|---|---|---|
| ファームウェア | Arduino(esp32 core 3.3.12、BLEスタックはNimBLE)、ボード `XIAO_ESP32C3` | `firmware/boat_controller/` |
| Webアプリ | React + TypeScript のPWA。GitHub Pagesで配信 | `webapp/` |

Web Bluetoothはhttpsが必須のため、Webアプリは船から配信せず、GitHub Pagesに置く。

## 2. ハードウェア

### ピン割当

| 信号 | XIAOピン | GPIO | 接続先 |
|---|---|---|---|
| ML_IN_A | D10 | 10 | 左モーター U3 IN_A |
| ML_IN_B | D9 | 9 | 左モーター U3 IN_B |
| MR_IN_A | D8 | 8 | 右モーター U4 IN_A |
| MR_IN_B | D7 | 20 | 右モーター U4 IN_B |

### 電源

単3電池2本。VM、VBATともに電池直結(約2〜3.2V)で、AM1025EAの電源範囲 2.0〜6.8V に収まる。XIAOにはU2(XCL103)で昇圧した3.3Vを供給する。

### AM1025EAの入力

| IN_A | IN_B | OUT_A | OUT_B | 動作 |
|---|---|---|---|---|
| L | L | Hi-Z | Hi-Z | 停止(待機モード) |
| H | L | H | L | 順方向 |
| L | H | L | H | 逆方向 |
| H | H | L | L | ブレーキ |

データシートはp.4とp.5/7で「正轉」の呼び方が逆だが、OUTがINに追従する点は一致している。本仕様では上の表の呼び方を使う。

## 3. モーター制御

| 項目 | 値 |
|---|---|
| PWM | 20kHz、10bit(データシートの入力範囲 20Hz〜65kHz の範囲内) |
| 指令範囲 | -100〜100(%) |
| 指令の変化速度 | 0→100% を約300ms |

**駆動方式:** スローディケイ(片側H固定、もう片側をPWM)。PWMのオフ期間はブレーキ状態になる。L/Lとの交互にしないのは、PWM周期ごとにICが待機モードへ入るのを避けるため(データシートに待機からの復帰時間の記載がない)。

| 指令 | IN_A | IN_B |
|---|---|---|
| 正(出力 d) | 100% | (1−d) |
| 負(出力 d) | (1−d) | 100% |
| 0 | L | L |

**回転方向:** 前進指令で逆に回るモーターは、スケッチ冒頭の `MOTOR_L_INVERT` / `MOTOR_R_INVERT` を `true` にする。

## 4. BLEプロトコル

| 項目 | 値 |
|---|---|
| デバイス名 | `SampleU-Boat` |
| サービスUUID | `7c1f0a10-5b3e-4d2a-9f61-2a8e4c7d1b00` |
| 指令キャラクタリスティックUUID | `7c1f0a11-5b3e-4d2a-9f61-2a8e4c7d1b00` |
| 指令のプロパティ | Write Without Response |
| ログキャラクタリスティックUUID | `7c1f0a12-5b3e-4d2a-9f61-2a8e4c7d1b00` |
| ログのプロパティ | Notify |
| 同時接続数 | 1台。切断後にアドバタイズを再開する |

### 指令フレーム(2バイト)

| バイト | 型 | 内容 |
|---|---|---|
| 0 | int8 | 左モーター指令(-100〜100、正が前進) |
| 1 | int8 | 右モーター指令(-100〜100、正が前進) |

- 範囲外の値は ±100 に丸める。
- 2バイト以外のフレームは破棄する(タイムアウトの計測も更新しない)。
- 認証やペアリングはない。Bluetoothの届く範囲にいる第三者も、船が未接続なら接続できる。

### ログ通知

船の動作ログを、改行で終わるテキストとして通知する。1回の通知は最大20バイトで、MTUに依存しない。受信側は改行まで連結して1行にする。

未送信の行は最大64行まで保持し、溢れると古い行から捨てる。購読されると保持していた行から順に送る。保持はRAM上なので、リセットや電源断で失われる。

各行は `<起動後のミリ秒> <本文>` の形式で、1行の長さは最大79文字。

| 本文 | 意味 |
|---|---|
| `boot reason=<理由> build=<日時>` | 起動。理由は `POWERON`、`BROWNOUT`(電圧低下)、`PANIC` など |
| `connected` / `disconnected` | 接続と切断 |
| `commands active` | 指令の受信が始まった |
| `failsafe stop: no command for <n>ms` | 受信が途切れて停止した |
| `failsafe stop: disconnected` | 切断で停止した |
| `st L<目標>><現在> R<目標>><現在> rx=<n> gap=<n>ms bad=<n> drop=<n> heap=<n>k` | 接続中に1秒ごとに出す状態 |

状態行の項目は次のとおり。`rx` は前回の状態行以降に受信したフレーム数(正常なら約20)、`gap` は同期間の最大受信間隔、`bad` は不正フレーム数の累計、`drop` は捨てたログ行数の累計、`heap` は空きメモリ。

切断理由は、使用しているBLEライブラリのコールバックで取得できないため記録しない。

### 送信周期

Webアプリは接続中、50msごとに最新の指令を送る。値が変わらなくても送り、ハートビートを兼ねる。前の書き込みが完了していなければその周期は飛ばす。

## 5. フェイルセーフ

次のいずれかで、変化速度の制限を通さず、ただちに両モーターを停止(L/L)する。

| 条件 | 検出側 |
|---|---|
| 最後の有効フレームから500ms経過 | ファームウェア |
| BLE切断 | ファームウェア |
| 接続後、最初の有効フレームを受信する前 | ファームウェア |

Webアプリ側では、次の場合に操作入力を中立へ戻す。

| 条件 | 動作 |
|---|---|
| 画面が非表示になった | 停止フレームを1回送り、以後は送信を止める。表示に戻ると再開する |
| 接続が切れた | 送信を止め、STOPのラッチも解除する |
| 指を離した | 入力を0に戻す |

**限界:** 電源投入からファームウェアが動き出すまでの間は、ファームウェアで制御できない(9章の1)。

## 6. Webアプリ

### 対応環境

AndroidのChromeのみ。Web Bluetooth非対応のブラウザ(iPhoneのSafariなど)やhttps以外では案内を表示する。

### 操作モード

上部のタブで切り替える。選択は端末に保存する。

| モード | 操作 | 出力 |
|---|---|---|
| スティック | ジョイスティック1本(片手) | ミキシング |
| 左右独立 | 縦スライダー2本(両手) | 左右をそのまま出力 |
| スロットル+舵 | 縦スライダーで前後進、横スライダーで旋回(両手、横持ち向け) | ミキシング |

**ミキシング:** `左 = 前後進 + 旋回`、`右 = 前後進 − 旋回`。どちらかが ±100 を超えるときは、左右の比率を保って縮める。

スティックには半径の8%の不感帯がある。

### 共通の表示と操作

| 要素 | 内容 |
|---|---|
| 接続表示 | 未接続 / 接続中… / 接続済み / 切断されました。切断後は「再接続」と「船を選び直す」を出す |
| L/R出力 | 実際に送っている指令値を表示する |
| 最大出力 | 10〜100%(5%刻み)、初期値100%。全指令に掛ける。端末に保存する |
| STOP | 押すと解除するまで0を送り続ける。接続が切れると解除される |

### ログ画面

「ログ」ボタンで開く。船のログとアプリのログ(接続、切断、送信失敗、画面の表示切替)を、受信時刻とともに時系列で表示する。

| 操作 | 内容 |
|---|---|
| 保存 | テキストファイル `boat-log-<日時>.txt` をダウンロードする |
| クリア | 表示中のログを消す |
| 閉じる | 操縦画面に戻る |

アプリ側は最新5000行をメモリに保持し、ページを再読み込みすると消える。ログ画面を開くと操作入力は中立に戻るが、接続とハートビートは維持する。

### その他

接続中は画面の消灯を防ぐ(Wake Lock API)。PWAとして動作し、一度開けばオフラインでも起動できる。

端末の既定フォントでは漢字が中国語の字形になることがあるため、Google FontsのNoto Sans JPを使う。

## 7. 対象外

- 電池電圧の表示(電圧検出回路がない)
- 認証、ペアリング
- OTAアップデート
- iPhone対応

## 8. 変更時に揃える箇所

次の値はファームウェアとWebアプリの両方にあるので、同時に変更する。

| 値 | ファームウェア | Webアプリ |
|---|---|---|
| UUID | `SERVICE_UUID`、`COMMAND_CHAR_UUID`、`LOG_CHAR_UUID` | `webapp/src/lib/protocol.ts` |
| 指令範囲 | `COMMAND_MAX` | `COMMAND_MAX` |

送信周期(`SEND_INTERVAL_MS`)は、タイムアウト(`COMMAND_TIMEOUT_MS`)より十分短くする。

## 9. 回路上の注意

回路は製作済みのため変更しない。

1. **起動時にモーターが回る可能性:** D9(GPIO9)はXIAO基板上でプルアップされ、IN_AはICの内蔵100kΩでプルダウンされる。このためファームウェアが動き出すまで、左モーターが L/H で駆動される可能性がある。D8も起動時の状態によっては右モーターに影響する。実機で確認する。
2. **IN入力電圧:** データシートp.2の注記では、IN入力はVCC以下が条件。XIAOのH出力3.3Vは電池電圧を上回り、消耗時ほど差が大きくなる。影響の程度はデータシートから判断できないので、実機で確認する。
3. **コンデンサ:** データシートはモーター端子間の0.1µF(p.6のC4)も必須としている。回路図のC8/C11はICの出力側(p.6のC3)に相当するので、モーター側にも付ける。
4. **USBと電池:** XIAOの3V3にU2の出力が直結されているため、USBと電池は同時につながない。書き込みはXIAOを基板から外して行う。
